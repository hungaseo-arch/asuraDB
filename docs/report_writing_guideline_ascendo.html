01

목적과 기본 원칙

1.1 목적

보고받는 사람이 다음 6가지를 파악하고 의사결정할 수 있도록 작성 기준을 통일

  • 무슨 일이 발생했는가
  • 현재 상태와 영향은 무엇인가
  • 원인은 무엇인가
  • 선택 가능한 대안은 무엇인가
  • 어떤 조치를 언제 누가 실행하는가
  • 보고받는 사람이 무엇을 승인·선택·지시해야 하는가
보고서의 정의작성자가 아는 내용을 나열하는 문서가 아니라 보고받는 사람의 이해와 판단을 돕는 문서. 품질 평가 기준은 정보량이 아닌 이해 속도와 의사결정 가능성

02

작성 전 판단

2.1 중요성 (Materiality / Materialitas)

  • 사안의 중요도에 따라 보고 여부, 범위(누구까지), 방법(구두·메신저·메일·보고서) 결정
  • 외부 고객 요청·컴플레인 : 반드시 서면 보고
  • 품질·안전·법무·재무상 중대한 이슈 : 서면 작성 및 이력 관리
  • 사업·생산·현금흐름에 중대한 영향이 예상되는 사안 : 선보고 후보고서
  • 일반 사안 : 담당자의 전문적 판단 또는 상급자 지시에 따름. 미보고와 과잉 보고 모두 지양
  • 구두·메신저로 종결된 사항도 중요하거나 이력 관리가 필요하면 문서화하여 보관 (회사의 자산)

2.2 적시성 (Timeliness / Ketepatan Waktu)

  • 보고 시점 3단계 : 문제 발생 가능성이 확인된 때, 실제 발생한 때, 조치 완료 또는 결과 확인 때
  • 문제 발생 조짐이 있으면 구두·메신저·메일로 1차 보고 후 추이를 계속 업데이트, 최종적으로 보고서 작성
  • 시급하고 중요한 사안은 선보고 후보고서 원칙
  • 지적받은 뒤에야 보고하는 방식은 즉시 개선 대상

출처 : '06년 보고서 작성 관련 사장님 교육 내용 발췌 (160601 가이드 2쪽)

2.3 작성 전 확인 질문

  • 기존에 동일·유사한 검토 또는 보고가 있었는가. 기존 담당자·관련 임원에게 과거 경위를 확인했는가
  • 현재 보고가 의사결정에 실제로 필요한가. 최종 의사결정권자는 누구인가
  • 서면·메일·구두 중 어떤 방식이 적절한가
  • 수신자별 역할과 요청 사항이 분명한가
  • 별첨·엑셀·사진·계약서 등 근거 자료가 필요한가
  • 보고 시점과 다음 업데이트 시점이 정해져 있는가
03

분량과 구조

3.1 분량 기준

  • 기본 1장, 일반적인 최대 2장
  • 2장 초과 보고서(제품·설비 비교 분석, 시장·경쟁사 조사 등) : 앞부분에 1~2장 요약본 첨부
  • 세부 계산·원자료·참고자료 : 본문과 분리하여 별첨 구성
  • 1~2장으로 요약하지 못하는 것은 보고자가 내용을 충분히 파악하지 못했다는 의미
  • 분량 축소 자체가 목적은 아님. 의사결정에 필요한 정보는 남기고 반복·장황한 설명과 관련성 낮은 자료를 제거

3.2 표준 구조

  • 제목 → 요약 → 현황·배경 → 문제·원인 또는 검토 기준 → 대안·주요 내용 → 결론·제언 → 확인·승인 필요 사항 → 별첨
  • 첫 페이지 필수 요소 : 결론, 핵심 수치, 영향, 요청 사항

3.3 보고 유형별 구성

보고 유형기본 구성
문제 해결형현황·문제점 → 영향 → 주요 원인 → 개선 대책 → 의사결정 요청
제안·기획형배경·목적 → 현행 문제 → 대안 비교 → 주요 내용 → 비용·일정 → 기대 효과·리스크 → 승인 요청
결과 보고형개요(일시·장소·대상) → 주요 결과 → 계획 대비 차이 → 이슈 → 후속 조치
상황 보고형발생 개요 → 현재 상황 → 영향·위험 → 즉시 조치 → 추가 계획 → 지원·결정 요청
품의·결재형품의 목적 → 추진 배경 → 검토 내용 → 대안·비용 → 추진 일정 → 결재 요청

출처 : 160601 가이드 기본 구성 2종을 5종으로 확장

04

핵심 내용 작성 방법

4.1 결론 우선

  • 배치 순서 : 결론 또는 현재 판단 → 핵심 수치와 영향 → 필요한 의사결정 → 주요 근거 → 상세 내용과 별첨
  • 보고받는 사람이 첫 페이지에서 "무엇을 결정해야 하는가"를 알 수 있어야 함

4.2 독자 중심

  • 작성자가 아는 순서가 아닌 보고받는 사람이 판단하기 쉬운 순서로 작성 (易地思之)
  • 배경은 필요한 만큼만 작성, 처음 읽는 사람에게 필요한 이력만 요약
  • 관련성이 낮은 자료는 삭제하거나 별첨으로 이동
  • 약어·전문용어는 최초 사용 시 풀어 쓰고 괄호에 약어 표기
  • "적극 검토", "신속 추진", "향후 조치"처럼 기준이 불분명한 표현은 주체·기한·수치로 구체화

4.3 완전성 (Completeness / Kelengkapan)

  • 6하 원칙 : 누가(Who)·언제(When)·어디서(Where)·무엇을(What)·어떻게(How)·왜(Why) 누락 없이 확인
  • 분석 도구 : 4M(Man, Machine, Material, Method), 4P(Product, Price, Place, Promotion), MECE(중복 없이 누락 없이), 원인·영향·대책 매트릭스, 대안별 비용·효과·리스크 비교
  • 검토 범위 : 부서·지점 단위를 넘어 고객, 공급업체, 다른 부서, 현금흐름, 법무·품질·안전, 회사 전체 영향까지 입체적으로 검토

4.4 결론과 근거의 계층

상위 항목에 결론, 하위 항목에 근거를 종속시켜 작성. 결론과 근거를 동일 수준에 병렬 배치하면 보고받는 사람이 관계를 다시 해석해야 함

바른 예 (○)
  • □ A업체 설비 구매 필요
    • - 구매가격 낮음 : A업체 USD 80,000, B업체 USD 85,000
    • - 생산 품질과 납기 조건 우수
    • - 투자 회수 기간 2.1년으로 2안보다 짧음
틀린 예 (×) : 결론과 근거를 같은 수준으로 병렬 나열
  • □ A업체 설비 구매 필요 / □ 구매가격 낮음 / □ 생산 품질 우수

4.5 실행 가능성

요소구체화 내용
주체누가 실행하는가
시기언제 시작하고 언제 완료하는가
방법어떤 절차와 자원으로 실행하는가
비용얼마가 필요하며 예산 출처는 무엇인가

가능하면 완료 기준과 점검 지표도 함께 제시

대안과 데이터 작성

5.1 대안 비교

새로운 대안 제시 시 기존안 또는 다른 대안과 동일한 기준으로 비교. 장점만 나열하지 않고 비용·효과·리스크·실행 가능성·일정까지 비교

5.2 근거와 출처

  • 모든 핵심 주장에 근거 연결
  • 외부 자료 : 출처명·기준일·링크 또는 문서번호 표시
  • 내부 자료 : 담당 부서·추출일·시스템명 표시
  • 추정치·가정치·예측치는 명시적으로 구분, 반올림 차이는 각주로 표시
  • 본문·표·첨부 엑셀의 수치 대조
  • 참고·별첨 자료는 핵심 내용을 요약하여 본문과 연결

5.3 평균과 가중평균

  • 판매량·사용량·매출 비중이 다른 항목 비교 시 단순 평균 사용 금지
  • 단순 평균 : 각 비율을 동일 비중으로 계산 / 가중평균 : 판매량·사용량·매출액 등 실제 비중 반영
  • 예 : 규격별 판매량이 다른 마진율 비교 시 규격별 판매 비중을 반영한 가중평균 사용

5.4 데이터 제시

  • 정량 데이터는 표·그래프·핵심 수치로 제시
  • 정량화가 어려운 판단은 평가 기준과 판단 근거를 함께 기재
  • 정량·정성 자료 모두 결론과 연결하여 제시
06

문체와 표현

6.1 기본 문체 (명사형 개조식)

  • 문장 끝 : 명사 또는 "~함, ~음, ~필요, ~적용"으로 맺음. "~합니다, ~한다" 서술체 미사용
  • 마침표 : 한 항목의 문장이 하나이면 끝 마침표 생략. 둘 이상이면 문장 사이 마침표 유지
  • 과장·홍보성 표현, 상투적 마무리 문장, 불필요한 굵은 글씨 배제
권장 예시
  • 고객 클레임 원인 분석 및 재발 방지 대책 수립 필요
  • 1차 개선안 적용 후 불량률 3.0%까지 감소
  • 관련 부서 협의 후 10월 중 적용

6.2 쉬운 표현

  • 한 문장에 하나의 핵심 메시지만 배치
  • 불필요한 명사 나열과 중복 표현 축소
  • 약어는 최초 1회 풀어 쓰고 괄호에 약어 표기
  • 외국어는 한국어 표현 우선, 필요 시 병기
  • 모호한 표현 대신 주체·기한·수치 명시
  • 어려운 용어는 쉬운 말로 바꾸고, 대체가 어려우면 설명 추가
  • 한 문장이 길어지면 두 문장 이상으로 분리

출처 : 국립국어원 「쉬운 공문서 쓰기 길잡이」(2023.02.02), 행정업무의 운영 및 혁신에 관한 규정 제7조

6.3 영어·인도네시아어 병기

  • 형식 : 영어 / 인도네시아어 / 한국어
    • Credit Limit / Plafon Kredit / 여신 한도
    • Materiality / Materialitas / 중요성
    • Timeliness / Ketepatan Waktu / 적시성
    • Completeness / Kelengkapan / 완전성
  • 병기가 많아 가독성이 떨어지면 본문은 한국어로 쓰고 용어표를 별첨

6.4 기호와 콜론

  • 콜론 : "항목 : 내용" 형식, 앞뒤 공백 1칸. 시각(09:30), 비율(3:1), URL은 원형 유지
  • 기호 체계는 문서 전체에서 일관 사용
  • 권장 순서 : Ⅰ → 1 → (1) → ① → □ → - → ·

문서 형식과 표 작성

8.1 파일 형식

  • 작성 파일 형식 : 보고 목적과 협업 환경에 따라 선택 (한글, Word, Excel, PowerPoint)
  • 최종 보고서 : 수정이 불가한 PDF로 변환하여 전달
  • 전달 방법 : 이메일, 한비로(Hanbiro) 등 승인·공유 채널 활용
  • 원본 파일 : 산출·검증을 위해 작성 부서에서 별도 보관
  • 첨부 데이터 : 필요 시 Excel, 사진, 계약서 등 근거 자료 별첨

메일·전자결재

10.1 전자결재

  • 실행 전 상신 원칙. 실행 후 소급 결재 지양
  • 대면 보고가 끝난 사항도 결재자는 보고서·수치·첨부를 반드시 확인
  • 결재 요청 사항을 제목과 요약에 명시
  • 결재선은 실제 책임과 의사결정 권한에 맞게 설정

10.2 메일 보고

  • 본문 포함 사항 : 핵심 결론, 주요 수치·이슈, 수신자에게 요구하는 사항, 회신·실행 기한, 첨부 자료의 성격과 확인 위치
  • 메일 수신 : 수신 여부와 요청 사항에 언제·어떻게 대응할지 회신 (포워드된 메일도 동일)
  • 공동 책임은 무책임 : 수신자를 많이 지정할수록 담당자와 요청 사항을 분명히 기재

10.3 메일 포워드

  • 원문만 전달하지 않고 본문에 요약 : 원문 배경, 수신자가 알아야 할 영향, 요청 사항, 담당자와 기한, 원문 첨부 여부
  • 필요 시 수신자가 참고할 사항을 번역하여 본문에 기재 후 원문 첨부

작성 후 검증

내용 검증
  • 결론이 첫 페이지에 있는가. 제목과 결론이 일치하는가
  • 6하 원칙에 누락이 없는가
  • 결론·근거·대안의 계층이 명확한가
  • 주체·시기·방법·비용이 구체적인가
  • 승인·선택·지시 사항이 명확한가
  • 다음 조치와 다음 보고 시점이 정해져 있는가
수치 검증
  • 단위·통화·기준일이 있는가
  • 소계·합계·총계가 일치하는가
  • 가중평균이 필요한 곳을 확인했는가
  • 본문·표·첨부 엑셀의 수치가 일치하는가
  • 반올림 차이·추정치·환율 적용을 표시했는가
  • 오탈자·수치 오류는 논리가 훌륭해도 신뢰도 저하
표현·형식 검증
  • 한글 어문규범과 맞춤법을 확인했는가
  • 약어·전문용어를 설명했는가
  • 명사형 개조식과 날짜·시각·숫자·단위 표기가 일관적인가
  • 표 아래 출처를 기재했는가. 쪽번호와 첨부 목록이 맞는가
  • 오탈자·띄어쓰기·중복 표현을 점검했는가
