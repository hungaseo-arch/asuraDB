## 📐 데이터 구조 (SSOT)

| 영역 | 단일 진실원천(SSOT) | 적재 대상 테이블 | 화면 |
|---|---|---|---|
| **시장/경쟁 + 재무** | `data/kpi/<YYYY>.csv` | `kpi_metrics`(지표 정의) · `kpi_monthly`(월별 target/actual) | `Monitor.vue` |
| **마진 분석** | `sales analysis report_<YYYY-MM>.pdf` | `margin_months`(월 요약) · `margin_records`(brand/product/customer/item) | `Margin.vue` |

- `kpi_monthly` 유니크 키: `(metric_id, year_month)` → upsert 멱등.
- `margin_records` 유니크 키: `(year_month, axis, primary_key, coalesce(secondary,''))`.
- 시장/경쟁 지표 16종: `q_*`(판매량 pcs) / `a_*`(판매금액 USD) × 8제품(TBR·TBB·OTR·AGR·IND·Vulkan·Tube·Flap).
- 재무 4종: `fin_sales`(재무매출) · `fin_sga`(판관비) · `fin_op`(영업이익) · `fin_ord`(경상이익), 단위 USD.

## 🔄 정기 갱신 절차

### A. 시장/경쟁 + 재무 (월별)

권장 경로 — **CSV 갱신 → importer 재실행** (target+actual·전 지표 일괄):

```bash
# 1) data/kpi/<YYYY>.csv 의 ACHIEVEMENT 섹션에 해당 월 컬럼 채우기 (필요 시 TARGET도)
# 2) 파싱 검증 (DB 미반영)
uv run python collectors/kpi_importer.py --dry-run   # "✓ 모든 행 월합 = 시트 Sum" 확인
# 3) Supabase 반영
uv run python collectors/kpi_importer.py
```

- CSV는 **정상 UTF-8 한글**로 작성한다. importer는 정상 한글과 mojibake를 모두 매칭하지만, 신규 작성 시 깨진 인코딩을 만들지 않는다.
- importer가 막힌 환경에서는 동일 데이터의 **SQL upsert 파일**로 대체 적용 가능(아래 변경이력의 SQL 참조). 단 SQL만 넣으면 CSV(SSOT)와 어긋나므로 **CSV도 반드시 함께 갱신**한다.

### B. 마진 분석 (월별)

```text
1) 신규 'sales analysis report_<YYYY-MM>.pdf' 수령
2) 4개 섹션(BRANDs/PRODUCTs/CUSTOMERs/ITEMs)을 margin_records 형식으로 전사
3) seed_margin_<YYYY-MM>.sql 생성 (기존 월 delete 후 insert = 멱등)
4) 각 축 합계가 TOTAL과 일치하는지 검증 후 Supabase 반영
```

적용:
```bash
supabase db execute -f supabase/migrations/<파일>.sql
# 또는 Supabase SQL Editor 에 붙여넣기
```
