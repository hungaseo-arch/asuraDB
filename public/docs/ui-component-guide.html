2. 표시 계층 판단 기준

Inline vs Overlay

유사 컴포넌트(Accordion·Modal·Drawer·Popover)의 선택 기준은 표시 계층 하나로 정리됨 — 문서 흐름 안에서 늘어나는가(Inline), 화면 위에 새 층으로 뜨는가(Overlay).

Component한글계층등장 위치배경 조작주 용도
Accordion아코디언Inline제자리 확장(다중 섹션)가능FAQ, 긴 폼의 구획
Disclosure접이식 패널Inline제자리 확장(단일)가능더 보기, 상세 정보
Tabs탭Inline같은 자리에서 교체가능동급 콘텐츠 전환
Modal모달창Overlay화면 중앙 + 딤 배경차단결재 확인, 삭제 경고
Drawer드로어Overlay화면 가장자리 슬라이드설계에 따름상세 편집, 필터, 사이드 메뉴
Bottom Sheet바텀시트Overlay하단에서 상승(모바일)반차단모바일 액션 선택
Popover팝오버Overlay트리거 요소에 앵커링가능부가 설명, 소형 폼
Tooltip도움말Overlay호버 시 근접 표시가능아이콘 설명 전용
Toast토스트Overlay모서리 임시 표시가능저장 완료, 오류 통지

선택 절차

1. 사용자가 하던 작업을 반드시 중단해야 하는가? ├─ 예 ────────────────▶ Modal (삭제 확인 · 결재 승인/반려) └─ 아니오 │ 2. 내용이 화면 절반을 넘길 만큼 많은가? ├─ 예 ─────────────▶ Drawer (데스크톱) / Bottom Sheet (모바일) └─ 아니오 │ 3. 특정 요소에 붙는 부가 정보인가? ├─ 상호작용 있음 ─▶ Popover ├─ 설명 문구만 ───▶ Tooltip └─ 아니오 │ 4. 본문 구조의 일부인가? ├─ 예 ────────▶ Accordion / Tabs └─ 결과 통지만 ▶ Toast

금지 사항

  • Modal 중첩 금지 — 2단계 이상 깊이 필요 시 Drawer 또는 별도 페이지로 전환
  • Tooltip 내 버튼·링크 배치 금지 — 키보드·터치 접근 불가 (해당 경우 Popover 사용)
  • 단순 안내 목적의 Modal 사용 금지 — Toast 또는 Inline Alert로 대체
  • Accordion과 Tabs 혼용 금지 — 두 섹션의 동시 비교가 필요하면 Accordion, 아니면 Tabs

구분 기준 · Toast는 3~5초 자동 소멸(되돌릴 수 없는 정보 금지) · Progress는 소요 2초 이상 작업에 적용 · Skeleton은 레이아웃 이동 방지 목적 · Empty State는 원인과 다음 행동을 함께 제시함
/* Toast — 3.2초 자동 소멸 */
function toast(msg){
  const host = document.querySelector('.toast-host');
  const el = document.createElement('div');
  el.className = 'toast toast--ok';
  el.setAttribute('role','status');   /* 스크린리더 자동 낭독 */
  el.textContent = msg;
  host.appendChild(el);
  setTimeout(() => el.remove(), 3200);
}

function openDrawer(id){
  const d = document.getElementById(id);
  d.dataset.open = 'true';
  d.dataset.prev = document.activeElement.id;          /* 포커스 복귀 지점 저장 */
  document.body.style.overflow = 'hidden';             /* 배경 스크롤 잠금 */
  d.querySelector('.drawer__panel button')?.focus();
}

배색 비율 — 60·30·10

  • 배경 60% — Light Grey(#F0F0F0). 전체 바탕·대형 카드 레이아웃 배경. 넓은 여백 확보로 시각 피로 저감
  • 주요 요소 30% — Soft Blue(#E3F2FD) + Pastel Blue-Grey(#ECEFF1). 핵심 메뉴·전환 버튼(CTA)·상단 헤더
  • 강조 10% — Sage Green(#E8F5E9). 성공 알림·완료 상태·긍정 메시지에 한정 적용
i
본문 텍스트 색상 보정파스텔 계열은 배경(Fill) 용도에 최적화된 색상임. 본문 텍스트는 #546E7A보다 어두운 #37474F를 사용하여 WCAG AA 명도 대비(4.5:1)를 확보하고, #546E7A는 보조 텍스트·경계선 기준색으로 운용함.

13. 핵심 원칙

Prinsip Utama
  • 동일 기능에는 애플리케이션 전체에서 동일 컴포넌트를 사용함
  • 크기·색상·Typography·Spacing·State·Interaction의 표준을 사전 정의함
  • 기능 단위로 컴포넌트를 분리하여 재사용(Reusable) 가능하도록 구성함
  • 올바른 사용 방법(Do)과 권장하지 않는 사례(Don't)를 함께 문서화함
  • ERP 화면은 데이터 가독성 · 업무 처리 속도 · 일관성 · 사용자 오류 방지를 우선함
  • 액션 명칭은 전 과정에서 동일 어휘를 유지함 — "발주 확정" 버튼의 결과는 "발주 확정됨" 토스트로 표시
  • 신규 컴포넌트 추가 전 기존 컴포넌트의 Variant로 해결 가능한지 먼저 검토함
